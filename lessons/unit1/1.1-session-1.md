# Module 1.1, Session 1: Where Things Live

Unit 1: Systems programming · 2026-11-19

## Mini-lesson

### The map of a running process

Every running program on x86-64 Linux has the same broad layout. From low addresses to high:

```
low   .text     your machine code (read + execute)
      .rodata   string literals, const tables (read-only)
      .data     globals/statics with nonzero initializers
      .bss      globals/statics that start at zero (no space in the file)
      heap      malloc grows this upward            ↑
      ...       shared libraries, mmap regions
      stack     grows downward; locals and return addresses   ↓
high  kernel    (off-limits from user mode)
```

Once this map is in your head, many C mysteries reduce to one question: **which region is this in, and what are that region's rules?**

The first four regions come straight from sections in the ELF file on disk; the loader maps them into memory with the matching permissions. Heap and stack don't exist in the file at all; they are created at run time. That's why a 1 MB zeroed `static char buf[1 << 20];` doesn't make your binary 1 MB bigger: `.bss` only records its size.

### Four rules from the diagnostic

1. **String literals live in `.rodata`.** `char *s = "hello";` makes `s` point at read-only bytes inside the binary. Writing `s[0]` is undefined behavior and usually segfaults. `char s[] = "hello";` instead copies the bytes into a writable stack array.

2. **Statics and globals that start at zero live in `.bss`.** They are zeroed before `main` runs. All-zero bits is 0 in two's complement; `INT_MAX` is `0x7FFFFFFF`. An `int` is 4 bytes on x86-64 Linux.

3. **Signed overflow is undefined behavior, not wraparound.** Unsigned arithmetic wraps; signed does not. Because the compiler may assume UB never happens, it can fold `x + 1 > x` to true. The compiler optimizes against the language rules, not the hardware.

4. **`volatile` means "every access is observable."** The compiler must perform each read and write against memory and may not cache the value in a register. It does *not* make access atomic and does *not* order memory between threads. Real uses: memory-mapped hardware registers, signal handlers, `setjmp`.

Also worth memorizing now: under the System V x86-64 calling convention, integer arguments go in **rdi, rsi, rdx, rcx, r8, r9**, and the return value comes back in **rax**. You'll see these constantly from Module 1.3 on.

## Practicum

### Part A: UB exploration (about 45 minutes)

Work in `unit1/1.1-c/ub/`. Put each of these into its own small program:

```c
/* a */ char *s = "hello"; s[0] = 'H';
/* b */ int *make_counter(void) { int n = 0; return &n; }
/* c */ int x = INT_MAX; printf("%d\n", x + 1 > x);
```

- Compile each twice: `gcc -O0` and `gcc -O2 -Wall -Wextra`. Note what changes: crashes, warnings, output.
- Find `"hello"` in the binary with `readelf -S a.out` and `objdump -s -j .rodata a.out`.
- Rebuild with `-fsanitize=address,undefined` and read what the sanitizers report.
- Write a few lines on what surprised you in `unit1/1.1-c/ub/NOTES.md`.

### Part B: an arena allocator (rest of the week)

Work in `unit1/1.1-c/arena/`. Implement this API in `arena.h` and `arena.c`:

```c
typedef struct Arena Arena;
Arena *arena_create(size_t capacity);
void  *arena_alloc(Arena *a, size_t size, size_t align); /* align: power of two */
void   arena_reset(Arena *a);   /* free everything at once, keep the buffer */
void   arena_destroy(Arena *a);
```

**Done when:**

- [ ] `arena_alloc` returns correctly aligned pointers (`assert((uintptr_t)p % align == 0)`), and returns `NULL` when the arena is full or `align` is not a power of two.
- [ ] Absurd sizes such as `SIZE_MAX` return `NULL` instead of overflowing your pointer arithmetic. *This is the subtle one.* Hint: think about which quantity you compare against what, and whether that comparison can itself overflow.
- [ ] A `make test` target builds with `-std=c17 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined` and runs tests for alignment, exhaustion, reset-and-reuse, and the overflow case, all passing cleanly.
- [ ] Stretch: when the current block fills, chain a new block instead of returning `NULL`.
